# Ordered backend comparison harness

HTTP now uses the production `rendezqueue::OrderedServer` in `src/ordered.rs`.
This crate reexports that implementation. Public `rendezqueue::Server` remains
the vector reference. Only live test helpers and benchmark baselines are kept
here; obsolete candidate implementations are not shipped.

## Layout and behavior

- SID-indexed newest-first rows. Lookup does not reorder; successful registration
  inserts/moves its own row to the front. Discovery still scans in exact order.
- Production HTTP keeps a separate oldest-refresh-first linked map, one timer per
  live SID. Only successful input refreshes itself. Inclusive expiry removes due
  heads by SID; peers and generations expire independently. Duration::MAX works.
- Production timestamps are sampled inside each room's mutex. The independent
  reaper still runs during idle/stalled socket I/O and joins on listener drop.
- The local `Room`/`Rooms` types in this harness are pure clocked test helpers,
  not the production adapter or its reaper. They require nondecreasing time.
- Physical policy lives in production `src/ordered_policy.rs`, outside the pure
  serve call graph.
- No pair grouping: admitted `b→a` and `c→a` share minimum `a`. Missing peers are
  not synthesized; logical key consistency and uniqueness are preserved.

## Tests and reproduction

Run `sh test/comparison/run-checks.sh` from the repository root, or invoke the
script by its path from any directory. It uses ordinary Cargo and the selected
Rust toolchain (with rustfmt and Clippy). Set `CARGO` to an executable wrapper if
needed. Keep `CARGO_TARGET_DIR` and download caches on persistent local disk when
sources are on network storage; run CPU-heavy checks under nice/ionice.

The script checks debug/release tests, builds both benchmark binaries, regenerates
both raw reports, then validates them. From the repository root, run
`python3 test/comparison/summarize.py > test/comparison/benchmark-summary.md`
to refresh the summary after taking new measurements.

- Five core/harness tests include 131,072 arbitrary request/fault transitions,
  every outcome and complete ordered state against the vector reference,
  per-SID expiry/compaction checks, and a negative order-corruption control.
- Twenty-two cache-source tests compile the real current HTTP cache and a frozen,
  byte-exact vector cache. They include 32,768 seeded request/sweep transitions,
  comparing outcomes, refresh timestamps and room counts across multiple rooms,
  plus their deterministic expiry/recovery/invariant controls and six new
  registry lifecycle/concurrency/budget tests.
- Two report tests validate all 240 raw timing records and complete trial grids
  using the pinned SxPB parser. Debug and release profiles are checked.

The vector-cache snapshot is `src/bin/legacy_server/expiry.rs`, copied byte-exact
from the pre-migration vector implementation (SHA256
`57bdce6695b1c73abde5602b7501f02b68b9eae9a8039b9b6a16f7a254b4bf4d`).
Its core symlink still resolves to unchanged vector `src/server.rs`.
`cache-benchmark.rs` separately imports the actual production cache source.
Rustfmt skips these read-only imports; neither cache is a handwritten benchmark
replacement. The relative fixture link supports their real embedded tests.

## Measurements

`benchmark.sxpb` has 180 core/local-helper timings; `cache-benchmark.sxpb` has 60
frozen-vector/current-production cache-registry timings. Three trials ×2000 warm
calls, row counts 2/16/128/1024/8192, 32/4096-byte core payloads. Setup and initial
state cloning are untimed. Per-call output allocation/destruction is timed.
Core comparisons verify complete final ordered states; cache comparisons verify
outcomes/room counts but do not inspect private rows directly.

`benchmark-summary.md` is generated by `python3 summarize.py`; raw reports retain
all trials. The core benchmark's `clocked-hot-no-expired` and `expiry-burst`
cases measure its local clocked helper. Only `cache-benchmark.sxpb` measures the
actual production cache type through its explicit sequential clock/full-maintenance
hooks, including its registry/room locks but **no HTTP or concurrent dispatch**.
Production background maintenance uses the bounded incremental method instead.
Small-room and bulk-expiry regressions are retained, not hidden. Discovery and
large expiry batches remain linear; compaction is amortized, not worst-case
constant. Linked nodes and duplicate SID keys add metadata. No RSS, hard-memory,
HTTP-throughput or DoS guarantee follows.

Machine: atomman AMD Ryzen 9 7945HX, Linux x86_64, rustc 1.99.1 / LLVM 23.1.1.
No CPU/frequency isolation; hashes are randomized. Fixed seed 0 denotes input
generation, not hash seeding.

Formal verification and cross-language checks are maintained separately in
`rendezqueue-lean`. This comparison harness runs entirely in Rust.
